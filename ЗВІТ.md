## 2. Опис предметної області

Предметна область проєкту — **інтернет-магазин меблів**. Система «MebliHub» автоматизує процес продажу меблів через веб-інтерфейс та охоплює такі бізнес-процеси:

- **Каталог товарів** — перегляд, пошук та фільтрація меблів за назвою, ціною, наявністю на складі.
- **Авторизація та реєстрація** — система ролей (USER / ADMIN) з JWT-автентифікацією.
- **Оформлення замовлень** — створення замовлення із прив'язкою до товару та користувача, автоматичний розрахунок вартості.
- **Адміністрування** — CRUD-операції з товарами, перегляд усіх замовлень, аналітика продажів.

Основні сутності предметної області:
| Сутність | Опис |
|---|---|
| Товар (Product) | Меблевий виріб з назвою, описом, ціною, зображенням та кількістю на складі |
| Користувач (User) | Клієнт або адміністратор системи |
| Замовлення (Order) | Факт придбання товару конкретним користувачем |

## 5. Проєктування структури БД

База даних `furniture_marketplace` складається з трьох колекцій:

```
furniture_marketplace
├── users        — користувачі системи
├── products     — каталог товарів (меблів)
└── orders       — замовлення
```

### Зв'язки між колекціями

```
users (1) ──── (*) orders ──── (1) products
  │                  │                │
  │ _id ◄────── userId          productId ───► _id
  │                  │
  │           productName (денормалізоване)
```

- Зв'язок `users → orders`: один користувач може мати багато замовлень (1:N). Зберігається через поле `userId` у документі замовлення.
- Зв'язок `orders → products`: кожне замовлення прив'язане до одного товару. Поле `productName` денормалізоване для швидкого відображення без додаткових JOIN-запитів.

### Індексація
- Колекція `users`: унікальний індекс на полі `email` (`@Indexed(unique = true)`).
- Автоматичне створення індексів увімкнене через `spring.data.mongodb.auto-index-creation=true`.

## 8. Приклади запитів

### 8.1. find() — пошук документів

**Spring Data (derived query):**
```java
// Репозиторій — автоматична генерація запиту за назвою методу
List<Product> findByPriceBetween(BigDecimal minPrice, BigDecimal maxPrice);
```
**Еквівалент MongoDB:**
```javascript
db.products.find({ price: { $gte: 5000, $lte: 20000 } })
```

**MongoTemplate (Criteria API):**
```java
// Побудова запиту програмно через Criteria
List<Criteria> conditions = new ArrayList<>();
conditions.add(Criteria.where("name").regex("диван", "i"));
conditions.add(Criteria.where("price").gte(1000).lte(50000));
conditions.add(Criteria.where("stock").gt(0));

Query query = new Query(new Criteria().andOperator(conditions.toArray(new Criteria[0])))
        .with(pageable);
List<Product> products = mongoTemplate.find(query, Product.class);
```
**Еквівалент MongoDB:**
```javascript
db.products.find({
  $and: [
    { name: { $regex: "диван", $options: "i" } },
    { price: { $gte: 1000, $lte: 50000 } },
    { stock: { $gt: 0 } }
  ]
}).skip(0).limit(10)
```

### 8.8. Фільтрація

**@Query — складний фільтр:**
```java
// Доступні товари: ціна не більше maxPrice І є на складі
@Query("{ 'price': { $lte: ?0 }, 'stock': { $gt: 0 } }")
List<Product> findAffordableInStock(BigDecimal maxPrice);
```
**Еквівалент MongoDB:**
```javascript
db.products.find({ price: { $lte: 15000 }, stock: { $gt: 0 } })
```

**@Query — пошук за regex у кількох полях ($or):**
```java
@Query("{ $or: [ { 'name': { $regex: ?0, $options: 'i' } }, { 'description': { $regex: ?0, $options: 'i' } } ] }")
List<Product> findByNameOrDescriptionContaining(String pattern);
```
**Еквівалент MongoDB:**
```javascript
db.products.find({
  $or: [
    { name: { $regex: "диван", $options: "i" } },
    { description: { $regex: "диван", $options: "i" } }
  ]
})
```

**@Query — проекція полів (повернення лише потрібних полів):**
```java
@Query(
  value  = "{ 'price': { $gte: ?0, $lte: ?1 } }",
  fields = "{ 'name': 1, 'price': 1, 'imageUrl': 1, 'stock': 1 }",
  sort   = "{ 'price': 1 }"
)
List<Product> findByPriceRangeProjected(BigDecimal minPrice, BigDecimal maxPrice);
```
**Еквівалент MongoDB:**
```javascript
db.products.find(
  { price: { $gte: 1000, $lte: 20000 } },
  { name: 1, price: 1, imageUrl: 1, stock: 1 }
).sort({ price: 1 })
```

**@Query — фільтрація масивів ($size, $all):**
```java
// Юзери, які мають лише роль USER (не адміни)
@Query("{ 'role': { $size: 1, $all: ['USER'] } }")
List<UserEntity> findPureUsers();
```
**Еквівалент MongoDB:**
```javascript
db.users.find({ role: { $size: 1, $all: ["USER"] } })
```

### 8.9. Aggregation Pipeline

#### Статистика товарів

**Java (MongoTemplate):**
```java
Aggregation aggregation = Aggregation.newAggregation(
    Aggregation.group()
        .count().as("totalCount")
        .min("price").as("minPrice")
        .max("price").as("maxPrice")
        .avg("price").as("avgPrice")
        .sum("stock").as("totalStock")
);
AggregationResults<Document> results =
    mongoTemplate.aggregate(aggregation, "products", Document.class);
```

#### Виручка по товарах (GROUP BY)

**Java (MongoTemplate):**
```java
Aggregation aggregation = Aggregation.newAggregation(
    Aggregation.match(Criteria.where("status").is(OrderStatus.CONFIRMED)),
    Aggregation.group("productId", "productName")
        .count().as("orderCount")
        .sum("totalPrice").as("totalRevenue"),
    Aggregation.project("orderCount", "totalRevenue")
        .and("_id.productId").as("productId")
        .and("_id.productName").as("productName"),
    Aggregation.sort(Sort.Direction.DESC, "totalRevenue")
);
AggregationResults<Document> results =
    mongoTemplate.aggregate(aggregation, "orders", Document.class);
```
**Еквівалент MongoDB:**
```javascript
db.orders.aggregate([
  { $match: { status: "CONFIRMED" } },
  {

      orderCount:   { $sum: 1 },
      totalRevenue: { $sum: "$totalPrice" }

  {
    $project: {
      productId:    "$_id.productId",
      productName:  "$_id.productName",
      orderCount:   1,
      totalRevenue: 1
    }
  },
  { $sort: { totalRevenue: -1 } }
])
```

## 9. Валідація даних та обробка помилок

### Валідація вхідних даних

Валідація реалізована через анотації **Jakarta Validation** на рівні DTO (Data Transfer Objects):

**ProductRequest:**
```java
public record ProductRequest(
    @NotBlank @Size(max = 100) String name,           // назва обов'язкова, до 100 символів
    @Size(max = 1000) String description,             // опис до 1000 символів
    @NotNull @DecimalMin("0.01") BigDecimal price,    // ціна обов'язкова, мінімум 0.01
    String imageUrl,                                   // URL зображення (необов'язковий)
    @Min(0) Integer stock                              // кількість >= 0
) {}
```

**OrderRequest:**
```java
public record OrderRequest(
    @NotBlank String productId,          // ID товару обов'язковий
    @NotNull @Min(1) Integer quantity    // кількість >= 1
) {}
```

**RegistrationRequest:**
```java
public record RegistrationRequest(
    @NotBlank @Size(max = 50) String name,           // ім'я обов'язкове
    @NotBlank @Size(max = 50) String lastName,       // прізвище обов'язкове
    @NotBlank @Email @Size(max = 100) String email,  // валідний email
    @NotBlank @Size(min = 6, max = 100) String password  // пароль 6-100 символів
) {}
```

**LoginRequest:**
```java
public record LoginRequest(
    @NotBlank @Email @Size(max = 100) String email,
    @NotBlank @Size(min = 6, max = 100) String password
) {}
```

Активація валідації здійснюється через анотацію `@Valid` на рівні контролера:
```java
@PostMapping
public ResponseEntity<Product> createProduct(@Valid @RequestBody ProductRequest request) { ... }
```

### Глобальна обробка помилок

Реалізована через `@RestControllerAdvice` — централізований обробник виключень:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // Помилки валідації — повертає map з назвами полів та повідомленнями
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handleValidation(...) {
        // {"name": "must not be blank", "price": "must not be null"}
    }

    // Бізнес-логіка (товар не знайдено, email вже існує тощо)
    @ExceptionHandler(RuntimeException.class)
    public ResponseEntity<Map<String, String>> handleRuntimeException(...) {
        // {"error": "Product not found: 123"}
    }

    // Невірні облікові дані
    @ExceptionHandler(BadCredentialsException.class)
    public ResponseEntity<Map<String, String>> handleBadCredentials(...) {
        // {"error": "Invalid email or password"}
    }
}
```

### Бізнес-валідація на рівні сервісів

```java
// Перевірка існування товару перед видаленням
if (!productRepository.existsById(id)) {
    throw new RuntimeException("Product not found: " + id);
}

// Перевірка дублювання email при реєстрації
if (userRepository.findByEmail(request.email()).isPresent()) {
    throw new RuntimeException("Email already exists.");
}

// Перевірка існування товару при створенні замовлення
Product product = productRepository.findById(request.productId())
    .orElseThrow(() -> new RuntimeException("Product not found: " + request.productId()));
```

### Захист на рівні БД
- Унікальний індекс на `email` у колекції `users` — запобігає дублюванню на рівні MongoDB.
- Паролі зберігаються у хешованому вигляді (BCrypt).

## 10. Висновки

У результаті виконання індивідуального завдання було розроблено повнофункціональний веб-додаток **MebliHub** — маркетплейс меблів з використанням нереляційної бази даних MongoDB.

### Реалізовані вимоги:

| Вимога | Статус | Деталі реалізації |
|---|---|---|
| `find()` | Реалізовано | `findAll()`, `findByPriceBetween()`, `findByStockGreaterThan()`, `searchWithFilters()` (MongoTemplate) |
| `findOne()` | Реалізовано | `findById()`, `findByEmail()` |
| `insertOne()` / `insertMany()` | Реалізовано | `save()` для одного документа, `saveAll()` для кількох |
| `updateOne()` | Реалізовано | `save()` з існуючим ID |
| `deleteOne()` | Реалізовано | `deleteById()` |
| Сортування | Реалізовано | Derived queries (`OrderByCreatedAtDesc`, `OrderByPriceAsc`), `@Query(sort=...)`, `Aggregation.sort()` |
| Фільтрація | Реалізовано | Derived queries, `@Query` з `$regex`, `$gte/$lte`, `$or`, `$size/$all`; MongoTemplate Criteria API |
| Aggregation Pipeline | Реалізовано | `$group` (COUNT, MIN, MAX, AVG, SUM), `$match`, `$project`, `$sort` |
| Валідація даних | Реалізовано | Jakarta Validation (`@NotBlank`, `@NotNull`, `@Min`, `@DecimalMin`, `@Email`, `@Size`) |
| Обробка помилок | Реалізовано | `@RestControllerAdvice` з обробниками для validation, runtime та auth помилок |

### Використані підходи роботи з MongoDB:

1. **MongoRepository** (Spring Data) — автоматична генерація запитів за назвою методу (derived queries).
2. **@Query** — явне задання MongoDB-запитів у JSON-форматі з підтримкою проекції та сортування.
3. **MongoTemplate + Criteria API** — програмна побудова складних динамічних запитів.
4. **MongoTemplate + Aggregation Pipeline** — аналітичні агрегації для статистики та звітності.

Додаток забезпечує повний цикл роботи з даними: від реєстрації користувача та перегляду каталогу до оформлення замовлення та аналітики продажів. Використання MongoDB дозволило гнучко зберігати документи з різною структурою та ефективно виконувати аналітичні запити через aggregation pipeline.
